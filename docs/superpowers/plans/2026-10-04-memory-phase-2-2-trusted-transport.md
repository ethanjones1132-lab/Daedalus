# Memory Phase 2.2 — Trusted Transport and Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Authenticate native-to-Bun memory preparation and diagnostics, persist recoverable turn lifecycle state, and invalidate every outstanding preparation before any production semantic memory or Session-binding mutation commits.

**Architecture:** Native Rust owns the operation gate, durable identity, and authority capability. Bun receives short-lived bounded envelopes into an in-memory registry and reports only authenticated metadata receipts. Every write path that changes memory eligibility or Session project binding calls the same native precommit coordinator; no SQLite lock is held across HTTP, and a live registry that cannot acknowledge invalidation blocks the mutation callback.

**Tech Stack:** Rust 2021/Tauri 2/rusqlite/reqwest/serde/chrono/uuid, owned process startup on Unix/Windows/WSL, Bun server with existing fetch/router patterns; no new store or service.

**Spec:** `docs/superpowers/specs/2026-10-04-memory-four-phase-design.md`; binding split `docs/superpowers/specs/2026-10-04-memory-phase-2-four-part-design.md`; parent contracts `docs/superpowers/plans/2026-10-04-memory-phase-2-live-recall.md`; predecessor `docs/superpowers/plans/2026-10-04-memory-phase-2-1-native-turns.md` and Phase 1 plan.

## Global Constraints

- Capability names are exactly `JARVIS_NATIVE_MEMORY_CAPABILITY` and `JARVIS_NATIVE_APP_INSTANCE_ID`; only the owned Bun child receives them. A side-effect-free entry bootstrap captures both and deletes them from `process.env` before dynamic imports/bootstrap paths or child-launch side effects; CLI children clone `process.env`, so deletion precedes environment construction.
- Internal routes: `POST /internal/memory/preparations`, `POST /internal/memory/invalidate`, `GET /internal/memory/turns/{preparation_id}`, and `POST /internal/memory/turns/{preparation_id}/ack`; bearer auth required, internal routes excluded from CORS.
- Registry caps: 256 unconsumed preparations, 256 unacknowledged consumed receipts, 128 KiB request bodies, 100 evidence refs and 64 KiB total evidence. TTL is 120 seconds; one consume; no new inference deadline.
- Native operation gate is entered by command/top-level mutation adapter **before acquiring the existing AppDb mutex**. Do not add invalidation inside an engine/store helper that already holds the SQLite mutex. No HTTP under SQLite mutex. For a live owned generation, precommit invalidation ACK is required before invoking mutation callback; failure returns `invalidation_unavailable`, preserves data/revision/events, and never stops a healthy server. Confirmed exited/replaced generation may proceed.
- Invalidate before mutation callback/commit, resolving the parent plan conflict in favor of the shared spec. Usage counter-only writes are explicitly excluded; all changes to knowledge, scope, eligibility, or Session binding are included.
- Preserve exact phase 2 DTOs/statuses, Phase 1 store contracts, permissions, and unrelated Session behavior. Bun never reads the App memory DB.
- Future test steps are documentation only. Do not create/run tests or live SQL checks. Authorized executable checkpoints are `/Users/charlottehughes/.cargo/bin/cargo check --manifest-path src-tauri/Cargo.toml`, `(cd server-jarvis && bun run typecheck)`, and applicable source `bun run build`; no installs.

## Review Focus

1. A concurrent mutation cannot commit while an old envelope remains consumable; tests `memory_mutation_clears_unconsumed_before_commit` and `memory_mutation_invalidation_failure_no_commit` belong to Task 4.
2. Unrelated, restarted, or HTTP-only Bun process never gains native authority; `native_memory_capability_owned_generation_only` belongs to Task 1.
3. Duplicate registration/receipt replay cannot overwrite a different turn or invent terminal success; `memory_receipt_authenticated_and_idempotent` belongs to Task 2.
4. Legacy CRUD, consolidation, Session deletion, and workspace rebind cannot bypass the gate; `all_semantic_write_paths_enter_precommit_gate` belongs to Task 4.
5. Restart/EOF cannot silently mark an unknown turn successful or leave native records falsely registered; `memory_recovery_does_not_reregister` belongs to Task 3.
